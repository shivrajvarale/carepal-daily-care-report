## How to read the two kinds of invented content

- **Caught by the verifier**: the model wrote a quote or number that is not in the note. The app removes it and shows it under *Removed by checker*.
- **Fabricated / invented (rows in bold)**: the field passes the substring check but the gold label says the note never gave it (for example 'no fever' becoming a temperature). String checks cannot catch these, so they are counted against gold labels.

## Analysis

The current evaluation run is dominated by provider errors rather than model-content errors: the first pass hit a 404 because `gemini-2.5-flash` is no longer available to new users, and the newer default then hit a 429 quota error. That means the checker never got a valid report to compare against gold labels, so the true accuracy picture is currently blocked by API availability and billing limits. The app logic itself is still structured to catch quote mismatches, number drift, and invented sections via the verifier; those are the cases the code is designed to reject before a family sees them. The main remaining risk areas are negation handling, Hindi/Hinglish wording, and multi-reading notes, which are exactly where the gold-label eval should be measured once the model is available again. The practical fix is to keep the model pinned to a supported Gemini name, monitor quota, and add a clear error path so users know the issue is external rather than a logic bug. This repo also needs a production-safe fallback or rate-limit warning so the app does not silently fail on a blocked API key.
